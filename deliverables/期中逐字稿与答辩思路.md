## 第 3 页 · 选题背景

> 我们选择这个题目，是因为「找厕所」虽然是一件小事，但它在特定场景下是一件很急的事。
>
> 我们在日常使用中发现四个问题：第一，地图搜索"厕所"时结果比较杂乱，常常混入商场内部点位、已关闭点位和名称相近的无关地点，用户需要逐个判断；第二，地图默认按综合权重排序，"最近的"未必排在最前；第三，有没有纸、洗手台是公共还是独立、是否有人清理，这些关键信息没有任何平台收录；第四，从搜到到走到，需要在地图、点评等多个应用之间切换，急迫场景下体验很差。
>
> 这四点，就是我们做这个项目的出发点。

**讲解要点**

- 四个痛点按顺序讲，每个一句话，不要展开。
- 强调「刚需 + 高频 + 现有工具没解决好」。

## 第 4 页 · 项目目标与选题意义

> 针对这些痛点，我们把项目目标概括为三个「得到」。

>
> 从课程角度看，这个选题场景虽小，但链路完整，覆盖了定位与地图、网络检索、本地数据存储、多界面架构、用户体系和跨应用通信等主要知识点，是一个适合课程大作业的题目。

## 第 8 页 · 系统设计：总体架构

> 系统采用三层结构。
>
> 最上面是界面层，负责页面展示和用户交互，不直接访问数据库和网络；中间是数据仓库层，用 ToiletRepository 统一封装定位、检索、排序、缓存、聚合等流程，是各个页面共用的统一数据出口；最下面是数据层，负责数据持久化和外部服务调用。
>
> 这样设计的好处是：数据来源变化时只需要修改仓库层，界面层不用动；各页面共用同一个数据出口，数据始终一致；同时职责边界清晰，方便我们两个人分工。

**讲解要点**

- 三层从上往下讲，配合 PPT 的箭头。
- 重点突出 Repository 的"统一数据出口"作用。

# 第二部分 · 技术栈扫盲（给组员看，PPT 上没有）

> 这部分是为组员准备的"看得懂版"说明。每一项都讲清四件事：**它是什么、干什么用、我们为什么选它、不用它会怎样**。
> 组员不需要背，只要被问到能说出大意即可。

## 1. Kotlin（开发语言）

- **是什么**：一种运行在 Java 虚拟机上的编程语言，是 Google 官方推荐的 Android 开发语言。
- **干什么用**：用来写整个 App 的业务代码，包括页面逻辑、数据处理、数据库操作。
- **为什么选它**：语法比 Java 简洁，同样的功能代码量更少；支持"空安全"，能在编译期减少空指针崩溃；内置协程，写异步代码更方便。
- **不用它会怎样**：改用 Java 也能开发，但代码更长、异步处理更繁琐，容易写出空指针问题。

## 2. Android Studio（开发工具）

- **是什么**：Google 官方推出的 Android 集成开发环境（IDE）。
- **干什么用**：写代码、看界面预览、编译打包、连接手机调试、查看运行日志。
- **为什么选它**：Android 官方唯一指定 IDE，功能最全、资料最多，遇到问题最容易查到解决方案。
- **不用它会怎样**：理论上可以用命令行加文本编辑器开发，但效率极低，调试和打包都非常麻烦。

## 3. Gradle（构建工具，PPT 中未展示）

- **是什么**：Android 项目的构建工具，负责把源代码、资源文件、第三方库打包成可以安装的 APK。
- **干什么用**：管理第三方依赖（比如高德 SDK、Room），执行编译、打包、签名等任务。
- **为什么选它**：是 Android 官方标准构建工具，Android Studio 默认集成；声明依赖只需一行配置，会自动下载。
- **不用它会怎样**：需要手动下载每一个第三方库、手动管理依赖关系，非常容易出错。可以理解成"项目的大管家"。

## 4. View + Material（界面体系，PPT 中未展示）

- **是什么**：Android 传统的界面开发方式（View 体系），加上 Google 的 Material Design 组件库。
- **干什么用**：View 负责页面布局，Material 提供现成的按钮、卡片、底部导航、弹窗、标签等组件。
- **为什么选它**：组件成熟、资料最多，用 XML 写布局和设计稿对应直观，适合课程项目快速出效果。
- **不用它会怎样**：也可以改用 Jetpack Compose（新的声明式 UI），但学习成本更高、资料相对少，本项目重心在功能与工程规范，所以选择更稳妥的方案。

## 5. 高德地图 Android SDK（地图定位）

- **是什么**：高德开放平台提供的 Android 开发工具包。
- **干什么用**：提供地图显示、混合定位、周边 POI 检索、逆地理编码、Marker 标注等能力。
- **为什么选它**：一个 SDK 就把地图、定位、检索、逆地理都集成好了，国内资料多、免费配额对课程项目完全够用。
- **不用它会怎样**：需要自己实现地图渲染、定位融合、空间检索，工作量巨大，不符合"不重复造轮子"的原则。

## 6. Room（本地数据库）

- **是什么**：Google 官方提供的数据库框架（ORM），底层是 Android 自带的 SQLite。
- **干什么用**：保存厕所信息、用户评价、账号信息等结构化数据，支持增删改查和统计查询。
- **为什么选它**：用注解声明表和字段，SQL 在编译期就会被校验，写错表名直接编译不过；自动生成实现代码，省掉大量样板代码。
- **不用它会怎样**：直接写 SQLite 也能存数据，但要手写建表、游标解析等大量重复代码，容易出错。

## 7. SharedPreferences（轻量文件存储，PPT 中未展示）

- **是什么**：Android 自带的轻量键值存储，本质是应用私有目录下的一个 XML 文件。
- **干什么用**：保存登录状态、最近一次定位、搜索历史这类简单数据。
- **为什么选它**：使用简单、读写快，适合小数据量；不需要为几个简单字段专门建数据库表。
- **不用它会怎样**：把所有数据都塞进数据库也能实现，但对简单的键值数据来说过于笨重。可以理解成"记几个小纸条"。

## 8. Kotlin 协程（异步处理）

- **是什么**：Kotlin 提供的异步编程方案。
- **干什么用**：处理数据库查询、网络请求等耗时操作，让它们不阻塞主线程。
- **为什么选它**：写起来像同步代码，逻辑清晰；主线程负责界面刷新，不能做耗时操作，协程可以把耗时任务放到后台。
- **不用它会怎样**：需要用线程加回调的方式处理，代码嵌套深、容易出错，也更容易造成界面卡顿。

## 9. Git + GitHub（版本管理）

- **是什么**：Git 是版本控制工具，GitHub 是基于 Git 的代码托管平台。
- **干什么用**：记录代码的每一次修改，支持多人协作、分支开发、代码评审。
- **为什么选它**：满足课程"团队协同开发工具使用"的考核要求，也是业界最通用的做法。
- **不用它会怎样**：多人改同一份代码时容易互相覆盖，出问题无法回退，也无法体现团队协作过程。

# 第三部分 · 项目答辩思路

## 1. 项目立意

- **真实需求**：找厕所是高频刚需，一旦需要就是十分钟内必须解决的事。
- **现有工具不足**：地图只有位置没有质量信息，排序也不按真实距离；点评类应用覆盖稀疏。
- **我们的切口**：不做大而全的平台，只把"找厕所"这一件事做顺、做透。

## 2. 产品价值

- **搜得到**：3 公里内检索，按真实球面距离排序。
- **看得懂**：三项结构化指标 + 用户评价，提前判断条件。
- **走得到**：一键唤起步行导航，未装高德自动回退网页版。

## 3. 技术选型思考（重点，老师可能追问）

**Q：为什么用 Kotlin 而不是 Java？**

> Kotlin 是 Google 官方首推的 Android 语言，语法更简洁，支持空安全，能在编译期减少空指针崩溃；内置协程，异步代码写起来更清晰。同样功能代码量比 Java 少。

**Q：为什么用 Room 而不是直接写 SQLite？**

> Room 是官方 ORM 框架，用注解声明表和字段，SQL 在编译期就被校验，写错表名直接编译失败，而不是等到运行时才报错；同时自动生成实现代码，省去手写游标解析的样板代码。

**Q：为什么选高德 SDK，不用别的地图？**

> 高德把定位、地图、POI 检索、逆地理编码集成在一个 SDK 里，接入成本低；国内资料多，个人开发者的免费配额对课程项目完全够用。

**Q：为什么用 XML 布局而不是 Jetpack Compose？**

> Compose 是新的声明式 UI，是未来方向；但课程项目更看重稳定和可讲解性。XML 加 Material 组件成熟、资料最多，和设计稿对应直观，我们能把精力放在功能与工程规范上。

**Q：Gradle 是什么？为什么需要它？**

> Gradle 是 Android 的构建工具，负责把代码、资源、第三方库打包成 APK，并管理依赖。比如我们要用高德 SDK，只要在配置里写一行依赖，Gradle 就会自动下载并加入项目。

**Q：SharedPreferences 和 Room 有什么区别，为什么两个都用？**

> Room 存结构化数据，比如厕所、评价、用户，需要查询和统计；SharedPreferences 存轻量键值，比如登录状态、最近定位。按数据特征选择存储方式，各取所长。

**Q：为什么要有数据仓库层（Repository）？**

> 把定位、检索、排序、缓存、聚合这些流程统一封装在一个出口，首页、地图页、榜单页都用它。这样数据来源变化时只改这一层，界面层不用动，也保证多页面数据一致。

# 第四部分 · 老师可能提问（20 条）

> 每条给出"参考答案要点"，不用背原文，抓住要点即可。

## A. 选题与价值类

**1. 这个题目会不会太小、太简单？**

> 工具虽小，链路完整。项目覆盖定位与地图、网络检索、数据库存储、多界面架构、用户体系和跨应用通信，每一环都能讲清设计理由，比做大而空的平台更能体现工程能力。

**2. 高德自己就能搜厕所，你们的差异在哪？**

> 三点差异：排序上我们按真实距离而非平台权重；信息上我们补充了结构化指标和用户评价；流程上从看到详情到导航是一步深链，不用反复切换。

**3. 目标用户是谁？使用频率高吗？**

> 游客、通勤的上班族与学生、户外工作者、带小孩的家庭。单人使用频率不高，但刚需属性极强，一旦需要就是十分钟内必须解决的事。

**4. 评价数据从哪来？冷启动怎么办？**

> 短期提供演示数据生成功能保证演示完整；中期靠搜厕所的人天然是刚用过的人来沉淀评价；长期如果接入云端，可以形成评价共享。

**5. 这个项目有什么创新点？**

> 一是把厕纸、洗手台、清理除味做成结构化指标卡；二是按真实球面距离排序；三是深链导航加网页回退，覆盖所有机型。

## B. 需求与设计类

**6. 为什么选这些功能？优先级怎么定的？**

> 以主流程为核心：定位、搜索、详情、导航是必做的高优先级功能；账号、评价、榜单是为了满足数据存储与创新性考核点；演示数据是为了保证演示效果。

**7. 界面为什么用蓝绿配色？**

> 蓝绿色系干净、清爽，和"卫生、公共设施"的场景比较契合；同时用统一的色系保证品牌一致性，用浅色底和卡片区分信息层次。

**8. 指标卡为什么设计成两行？**

> 结论行展示最新一条评价，反映最新使用者的反馈；统计行展示所有人的占比，避免单条评价的偶然性。两行结合，既有即时性又有统计性。

**9. 三张表为什么这么设计？**

> 对应厕所、评价、用户三类实体。评价通过 toiletId 和 userId 两个外键分别关联厕所和用户，形成两条一对多关系，结构清晰、便于扩展。

**10. 为什么厕所表主键用高德的 POI 标识？**

> 直接复用高德 POI 的唯一标识，能保证地图上的点和数据库里的记录一一对应，避免重复入库和数据不一致。

## C. 技术与实现类

**11. 为什么用 Kotlin 不用 Java？**

> 官方首推，语法简洁、空安全、支持协程，代码量更少、异步更清晰。

**12. Room 和直接写 SQLite 有什么区别？**

> Room 是官方 ORM，编译期校验 SQL，自动生成实现代码，省掉手写游标解析的样板代码，降低出错概率。

**13. 为什么用高德 SDK？要收费吗？**

> 高德把定位、地图、检索、逆地理集成在一起，接入成本低。个人开发者有免费配额，课程项目用量远低于上限，超出配额也只是调用失败，不会产生费用。

**14. 定位不准怎么办？**

> 使用混合定位（GPS、Wi-Fi、基站融合），精度约 30 米，对找厕所完全够用；如果定位返回的城市字段为空，还会用逆地理编码补齐城市区名。

**15. 为什么自己算距离，不直接用地图返回的排序？**

> 地图默认排序包含平台权重，不等于真实距离。我们重新计算球面距离并按由近到远排序，让"附近"名副其实。

**16. 什么是球面距离公式？**

> 用的是 Haversine 公式，把经纬度当成球面上的角度，换算成两点间的弧长。相比平面公式更准，相比椭球算法计算量更小，适合几公里范围的排序。

**17. 密码怎么存的？**

> 每个用户生成随机盐值，把盐值和密码拼接后做哈希，数据库只保存哈希结果。相同密码在不同用户处哈希值不同，可以防止彩虹表攻击。

**18. 导航怎么实现的？没装高德怎么办？**

> 通过隐式 Intent 匹配高德的导航协议直接唤起；如果设备没装高德，捕获异常后自动回退到网页版导航，保证所有机型可用。
