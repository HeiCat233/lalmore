## 1. 项目概述与选题背景

- 痛点：外出时找不到干净、就近的公共厕所；现有地图 App 搜索"厕所"结果杂乱、缺乏真实评价参考。
- 方案：一款"搜索附近厕所 → 查看真实评价 → 一键步行导航"的轻量工具 App。
- 创新点（对应"创新性与实用性 10 分"）：
  - 评价数据本地沉淀，按 Haversine 球面距离排序而非按 POI 权重排序，"附近"更真实；
  - 评价均分直接呈现在列表卡片上，搜索结果即带口碑参考；
  - 步行导航通过 URL Scheme 深链唤起，未安装高德时自动回退网页版，全机型可用。

## 2. 需求分析与功能设计

- 用例图/功能清单：定位 → 周边搜索 → 距离排序 → 地图 Marker → 详情查看 → 发布评价 → 导航。
- 数据设计：
  - `toilets` 表（收藏/缓存）：uid 主键、名称、地址、经纬度、时间戳；
  - `reviews` 表：自增主键、toiletId 外键关联、昵称、1~5 星、内容、时间戳；
  - SharedPreferences 文件：最近搜索关键词、首次启动标记。
  - 两级存储设计（SQLite + 文件）对应评分项"数据存储使用 10 分"。

## 3. 系统架构与技术选型

- 架构图（建议手绘或 draw.io）：UI 层（Activity/Adapter）→ 数据层（Room DAO）→ 服务层（高德 SDK）。
- 选型理由表：
  | 需求 | 选型 | 理由（不重复造轮子） |
  |---|---|---|
  | 地图/定位/POI | 高德 Android SDK（三合一组合包） | 官方维护、Maven Central 依赖、免费配额充足 |
  | 本地存储 | Room | 编译期 SQL 校验、免去 SQLiteOpenHelper 模板代码 |
  | 距离计算 | Haversine 自实现 | 轻量、可讲解原理 |
  | 导航 | URL Scheme 深链 | 不引入导航 SDK，包体小 |
- 集成踩坑记录（报告亮点）：
  - 三个独立高德包 Duplicate class 冲突 → 换官方组合包 `3dmap-location-search`；
  - SDK 强制隐私合规 API 必须在初始化前调用，否则定位错误码 12 / 地图白屏；
  - `keytool`/`sdkmanager` 环境变量路径问题。

## 5. 关键技术原理分析（技术深度提分）

- **混合定位原理**：GPS（卫星，室外精度 5m）+ Wi-Fi 指纹（室内 20~50m）+ 基站三角定位（粗略），高德 SDK 融合输出。
- **POI 检索与空间索引**：服务端对经纬度做 GeoHash 编码（二维经纬度 → 一维字符串，前缀相同即相邻），索引退化成 B+ 树范围查询，因此 3km 圆形搜索毫秒级返回。
- **Haversine 球面距离**：见 `DistanceUtil` 注释——平面勾股定理在球面上失效的原因与半正矢公式推导。
- **瓦片地图渲染**：金字塔层级（1 级 1 张 256px，每级 4 倍），客户端按视口加载 z/x/y 瓦片，矢量/栅格渲染差异。
- **坐标系**：WGS-84（GPS 原始）vs GCJ-02（国测局加密偏移，"火星坐标"），高德输出 GCJ-02 所以国内地图无偏移。
- **URL Scheme 跨 App 通信**：隐式 Intent 匹配协议 → 唤起已注册 App；缺失时 ActivityNotFoundException 回退。
- **Room 的编译期校验**：KSP 注解处理器在编译时把 SQL 字符串与实体字段比对，错误提前暴露。
